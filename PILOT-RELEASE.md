No experimental companion assets are included.

## Release and recovery

1. Bind all checks and independent review to final candidate SHA. Resolve scoped findings and recheck changed behavior.
2. Obtain Alex’s exact-revision content acceptance and separate merge/publication authorization. The book description, where present, is a disclosure candidate, not an already approved publication.
3. Before an authorized release, recheck current main, concurrent work, deployment source, triggers, output directory and current deployed revision. Never assume a merge is inert. Preserve the prior source and deployment receipt.
4. Only under the authorized release action, merge/publish the accepted revision through the established route. Verify actual live text, contact links, desktop/mobile behavior and certificate/domain routing.
5. If release verification fails, use the recorded previous deployment or a reviewed source revert under applicable owner authorization. Do not change DNS or delete history as a recovery shortcut.

No merge, deployment, auto-merge, live configuration, account/access changes or external correspondence is authorized by this candidate.
